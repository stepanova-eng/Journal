# Journal
Приложение для записи сообщений в файл с учетом их уровня важности.
## Описание проекта
Проект написан на языке программирования С++ для Ubuntu и представляет собой библиотеку динамической компоновки и консольное клиент-приложение, демонстрирующее работу первого модуля. Программа позволяет пользователю открывать файл и записывать туда сообщения различного уровня важности. В файле отображается текст сообщения, уровень важности и время добавления сообщения.
## Возможности
- создание файла журнала;
- открытие уже существующего файла журнала;
- создание и сохранение записи в журнале (текст сообщения, уровень важности, дата и время добавления сообщения);
- установка уровня важности по умолчанию;
- фильтрация сообщений по уровню важности (сообщение уровня ниже уровня по умолчанию записано не будет);
- смена уровня важности по умолчанию;
- многопоточная обработка сообщений;
- использование DLL-библиотеки для работы с журналом.

## Сборка
Сборка проекта выполняется с помощью утилиты `make` и файла *Makefile*.

Перед сборкой необходимо зайти в корневую папку проекта *Journal*. 

*Пример строки терминала:*
```
sofia@ubuntu:~Documents/Journal$
```
Далее введите команду `make`:

*Пример:*
```
sofia@ubuntu:~Documents/Journal$ make
```
После этого будет создано два файла: *Client* - клиент-приложение, и *libJournalDLL.so* - библиотека.

*Makefile* имеет четыре цели сборки: 
- `all` - полная сборка всего проекта;
- `Client` - сборка консольного клиент-приложения;
- `libJournalDLL.so` - сборка динамической библиотеки; 
- `clean` - очистка  файлов. Удаляет скомпилированные *Client* и *libJournalDLL.so*, при этом файлы журналов сохраняяются.

Чтобы собрать только одну цель, достаточно ввести `make` и цель сборки. Например: 
```
sofia@ubuntu:~Documents/Journal$ make clean
```
 или 
 ```
sofia@ubuntu:~Documents/Journal$ make libJournalDLL.so
 ```

---
*Примечание! При попытке скомпилировать *Client* до того, как будет собран файл библиотеки, терминал сообщит об ошибке, так как сборщик не сможет найти libJournalDLL.so, от которого зависит клиентское приложение.*
## Запуск
Запуск возможен при наличии всех скомипилированных файлов. Чтобы запустить проект, необходимо ввести две команды. Сначала `export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH`, затем `./Client`.

*Пример:*
```
sofia@ubuntu:~Documents/Journal$ export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
sofia@ubuntu:~Documents/Journal$ ./Client
```
После запуска в терминале появится приветствие и приглашение ввести данные.
## Использование 
### Ввод начальных данных
После запуска программы пользователь увидит приглашение ввести начальные данные:

- Имя файла журнала;
- Уровень важности по умолчанию.

|Ввод|Ограничения|
|---|---|
|Имя файла|Название файла может содеражть латинские буквы, кириллицу, цифры и специальные символы. Расширение файла может быть любым, а также отсутствовать. При отсутствии файла с введенным именем программа сама создаст такой файл. При пустом вводе программа попросит снова ввести значение|
|Уровень важности по умолчанию|Существует 4 уровня важности: low, medium, high, none (см. ниже, раздел "Уровни важности"). Программа понимает ввод в любом регистре при отсутствии различных опечаток. Может равняться NONE, если это значение введено пользователем. При пустом вводе программа попросит снова ввести значение|
### Создание сообщения
Далее пользователь увидит меню из 3 пунктов:

1. Сменить уровень важности по умолчанию;
2. Добавить сообщение;
3. Выйти из программы.

Чтобы выбрать пункт, необходимо ввести его номер.
#### 1. Сменить уровень важности по умолчанию: 
Пользователь вводит новый уровень важности по умолчанию. На новое значение действуют те же ограничения, что и при первоначальном вводе.
#### 2. Добавить сообщение
После выбора этого пункта пользователю предлагается ввести:
- уровень важности сообщения;
- текст сообщения.

|Ввод|Ограничения|
|---|---|
|Уровень важности сообщения|Любой из четырех вариантов в любом регистре без опечаток. Уровень сообщения также может быть пустым (нажатый пользователем enter), в таком случае он определяется как NONE|
|Текст сообщения|Ограничений нет, текст может состоять из любых символов, также текст может быть пустым|
#### 3. Выйти из программы
Программа завершает свою работу и выводит на экран сообщение об успешном закрытии.

### Уровни важности
В программе предусмотрены 4 уровня важности:
|Числовой эквивалент|Параметр|Перевод|
|---|---|---|
|1|LOW|низкий|
|2|MEDIUM|средний|
|3|HIGH|высокий|
|4|NONE|уровень важности отсутствует|

Сообщения, уровень важности которых ниже, чем уровень важности по умолчанию, в журнал записаны не будут.

*Пример для уровня важности по умолчанию MEDIUM:*
|Уровень важности сообщения|Состояние записи|
|---|---|
|LOW|не записано|
|MEDIUM|записано|
|HIGH|записано|
|NONE|записано|

## Принцип работы 
### Консольное приложение
Логика взаимодействия пользователя с программой реализована в консольном клиент приложении. В клиентском приложении реализована проверка ввода. После получения всех необходимых для сохранения сообщения в файл значений, програамма передает данные для записи в отдельный поток. Он работает в фоновом режиме параллельно с основным потоком, благодаря чему не происходит зависание пользовательского интерфейса при обработке сообщения. Все пользовательские сообщения сохраняются в очередь `std::queue`. Фоновый поток по умолчанию находится в состоянии ожидания сигнала от главного, когда он его получает, фоновый поток достает из очереди сообщение и записывает его в файл. Таким образом не возникает необходимости создавать для каждого сообщения новый поток и ни одна запись не будет утеряна.
### DLL-библиотека
Основная логика взаимодействия с журналом реализована в виде DLL-библиотеки. При инициализации библиотеки один раз открывается поток для работы с файлом, имя которого ввел пользователь.

Перед записью сообщения в журнал программа проверяет уровень важности сообщения, и, если он ниже уровня по умолчанию, сообщение записано не будет. 

При создании записи программа добавляет к ней время получения сообщения. Время берется из системы.
## Архитектура и ООП
Программа реализована в объектно-ориентированном стиле.
### Библиотека 
Библиотека состоит из двух модулей:
- `enum class Levels`, где перечисленный уровни важности в следующем порядке: *LOW, MEDIUM, HIGH, NONE*
- `class Message`

В классе **Message** находятся основные функции библиотеки:
|Функция|Назначение|
|---|---|
|`Message`|Конструктор класса: совершает открытие файла и установку уровня важности по умолчанию при инициализации библиотеки|
|`bool SaveMessage`|Запись сообщения в файл. Проверка уровня важности|
|`void ChangeLevel`|Смена уровня важности по умолчанию|
|`static string LevelToString` и `static Levels StringToLevel`|Перевод данных типа `enum class Levels` в тип данных `string` и наоборот|
|`~Message`|Деструктор класса: закрытие потока для работы с файлом|
### Клиент-приложение
Помимо основной функции int main() в клиентском приложении реализовано несколько вспомогательных модулей для более логичной и защищенной работы программы.
#### `struct Task`
Для удобного добавления сообщений пользователя в очередь для дальнейшей передачи в поток создана структура `struct Task`, полями которой являются `level` и `text`.
#### `string Lower`
Вспомогательная функция `string Lower` возвращает строку полностью в нижнем регистре для удобства пользователя (ему не придется следить за регистром вводимого текста) и защиты программы от разных вариаций ввода уровня важности.
#### `void SavingMessage`
Функция `void SavingMessage` передается в отдельный фоновый поток `thread` для записи сообщения в файл. Функция находится в режиме ожидания сигнала от программы. Когда она его получает, из очереди `queue` достается "задание" - текст и уровень важности сообщения - и передается в библиотечную функцию `SaveMessage` для записи в файл.

Благодаря вынесению переменной условия `cv`, отвечающей за ожидание сигнала к действию от основного потока, в отдельную функцию и ее дальнейшую обработку там, становится возможным единоразовое создание потока `thread savingMessageThread` при запуске программы до ее основного цикла `while`.

---
Поскольку в программе сразу два отдельных потока способны получить доступ к очереди заданий `queue taskQueue` и флагу остановки работы потока `stopThread`, в проекте используется `mutex`, блокирующий поток. После выхода из критической секции блокировка потока снимается.
